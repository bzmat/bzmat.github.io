Public-Key Cryptography in Ethereum (ECC)

1. Problem Description

The goal of this project is to demonstrate how Elliptic-Curve Scalar Multiplication operates as a one-way cryptographic function. Instead of the complex secp256k1 curve used by the Ethereum network, we will use a toy curve over a finite field for educational purposes.

  • Curve: y² ≡ x³ + 7 (mod 17)
  • Base Point (G): (1, 5)
  • Private Key (k): 6

3. Statistical Exploration

Repeating the experiment with different values of k reveals key statistical properties that differentiate elliptic curves (ECDLP) from standard cryptographic hash functions (e.g., SHA-256):

  • Uniform Distribution: On real curves, the (x, y) coordinates generated by random private keys are uniformly distributed across the finite field. No "valid" point is statistically more likely than another.
  • Input-Output Correlation: In ECC, scalar multiplication maps k linearly to Q through algebraic additions. However, reversing the process to find k from Q in the discrete field requires brute force (the discrete logarithm problem).
  • Avalanche Effect: Hash functions are designed so that changing 1 bit of the input alters roughly 50% of the output. ECC is not built with this bit-level constraint: changing k to k+1 predictably changes the resulting point (Q + G), although the coordinates appear visually uncorrelated due to the modulo operation.
  • Conclusion: Elliptic curve scalar multiplication is a Trapdoor One-Way Function (one-way with a mathematical "shortcut" if you possess the key), whereas a Hash is a one-way compression function without keys.
