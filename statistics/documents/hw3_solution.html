ECC Toy Scheme vs. Caesar Cipher & Statistical Attacks

1. ECC Toy Scheme Encryption & Decryption

Using the elliptic curve framework developed previously, we can implement a basic asymmetric encryption scheme (similar to ElGamal ECC).

  • The Keys: The private key k is a randomly chosen scalar. The public key is a point on the curve Q = kG.
  • Encryption: To encrypt a message M (mapped to a point on the curve), the sender generates a random ephemeral key r. The ciphertext consists of two points: C1 = rG and C2 = M + rQ.
  • Decryption: The receiver uses their private key k to compute kC1 = k(rG) = r(kG) = rQ. They then recover the message by subtracting this from C2: M = C2 - kC1.

2. The Caesar Cipher

The Caesar cipher is one of the simplest symmetric encryption techniques. It operates by substituting each letter in the plaintext with a letter a fixed number of positions down the alphabet.

  • Encryption: C = (P + k) mod 26, where P is the plaintext letter index (0-25) and k is the shift key.
  • Decryption: P = (C - k) mod 26.

3. Comparing ECC and Caesar Schemes

While both algorithms obscure data, their mechanics and security profiles are fundamentally different.

  • Key Space: The Caesar cipher has a trivial key space of 25 possible shifts. A proper ECC scheme (like secp256k1) has a key space of roughly 2256, making brute-force exhaustive search physically impossible.
  • Symmetry: Caesar is symmetric (same key for encryption/decryption). ECC is asymmetric (public key encrypts, private key decrypts).
  • Statistical Properties: The Caesar cipher preserves the underlying statistical frequency of the plaintext (e.g., the most frequent letter in the ciphertext corresponds to 'E' in English). ECC ciphertext points, however, appear uniformly distributed and pseudo-random, leaking no statistical information about the original message.

4. Statistical Cryptanalysis of the Caesar Cipher

Because the Caesar cipher preserves letter frequencies, we can crack it without an exhaustive search by analyzing the ciphertext. In English, the letter 'E' appears most frequently (~12.7%). By identifying the most frequent letter in a sufficiently long ciphertext and assuming it maps to 'E', we can immediately deduce the shift key k.

Effectiveness & Limitations: Frequency analysis is highly effective on large text corpora because the letter distribution reliably converges to language standards. However, on very short ciphertexts (e.g., a single word or sentence), the statistical variance is too high (e.g., 'Z' might be the most common letter by pure chance), causing the algorithm to fail. In those cases, an exhaustive key search (brute-forcing all 25 shifts) or n-gram scoring (evaluating common pairs like 'TH' or 'HE') is required.

5. Attacking the Restricted ECC Toy Scheme

In our toy ECC scheme, the private key k was restricted to a very small range to allow for manual calculations and easy visualization. This artificial restriction completely breaks the security of the system.

  • The Attack (Exhaustive Search): To recover the private key, an attacker simply iterates through all possible small values of i (1, 2, 3...) and computes i · G. As soon as i · G = Q (the public key), the attacker has found the private key k = i.
  • Comparison to Caesar Attack: The attack on the toy ECC is an exhaustive key search (brute force) made possible only by the artificially tiny key space. The attack on Caesar is a statistical attack exploiting structural weaknesses in the algorithm itself, regardless of how we search the keys.
  • Why it fails against real ECC: In standard secp256k1, the private key space is ≈ 2256. Calculating i · G iteratively for 2256 possibilities would take all the computers on Earth billions of years. Because ECC leaks no statistical data, there are no shortcuts like frequency analysis; the attacker is forced to solve the Elliptic Curve Discrete Logarithm Problem (ECDLP), which is currently computationally infeasible.
